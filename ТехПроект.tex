\section{Технический проект}

\subsection{Общее описание решения}

Для реализации программной библиотеки шифрования AES-128 используется язык программирования Common Lisp (реализация SBCL). Данный язык позволяет эффективно оперировать байтовыми массивами, использовать функциональный подход и гибкую систему типов.

Процесс разработки программной системы включает следующие этапы:
\begin{itemize}
	\item реализация арифметики в конечных полях $GF(2^8)$ для выполнения операций умножения и сложения байтов;
	\item проектирование структур данных для хранения таблиц замен и ключей;
	\item реализация алгоритма расширения ключа (Key Schedule);
	\item разработка логики раундовых преобразований шифрования и дешифрования;
	\item реализация механизма дополнения данных (Padding) для поддержки сообщений произвольной длины.
\end{itemize}

\subsection{Описание реализации алгоритма AES}

Реализация алгоритма базируется на официальном стандарте AES. В основе шифрования лежит итеративная обработка блока данных размером 128 бит (16 байт).

Процесс шифрования реализован через последовательность раундов. Для ключа длиной 128 бит выполняется 10 раундов. Каждый раунд (кроме последнего) включает четыре трансформации:

\begin{enumerate}
	\item \textbf{SubBytes (Замена байтов).} Нелинейная замена каждого байта блока по специальной таблице (S-Box). В программе это реализовано через обращение к глобальному массиву констант. Схема преобразования представлена на рисунке \ref{fig:subbytes}.
	
	\begin{figure}[H]
		\centering
		\includegraphics[width=0.7\linewidth]{aes_subbytes}
		\caption{Схема преобразования SubBytes}
		\label{fig:subbytes}
	\end{figure}
	
	\item \textbf{ShiftRows (Сдвиг строк).} Циклический сдвиг байтов в строках состояния. Поскольку в реализации используется одномерный массив, сдвиг выполняется путем перестановки индексов вектора (рисунок \ref{fig:shiftrows}).
	
	\begin{figure}[H]
		\centering
		\includegraphics[width=0.7\linewidth]{aes_shiftrows}
		\caption{Схема преобразования ShiftRows}
		\label{fig:shiftrows}
	\end{figure}
	
	\item \textbf{MixColumns (Перемешивание столбцов).} Линейное преобразование, где каждый столбец состояния умножается на фиксированный полином. Реализовано с использованием вспомогательной функции умножения в поле Галуа (рисунок \ref{fig:mixcolumns}).
	
	\begin{figure}[H]
		\centering
		\includegraphics[width=0.6\linewidth]{aes_mixcolumns}
		\caption{Схема преобразования MixColumns}
		\label{fig:mixcolumns}
	\end{figure}
	
	\item \textbf{AddRoundKey (Добавление раундового ключа).} Побитовое сложение (XOR) текущего состояния с раундовым ключом.
\end{enumerate}

В последнем раунде исключается операция MixColumns. Дешифрование реализовано как выполнение обратных операций в обратном порядке.

\subsection{Проектирование структур данных}

Ключевым решением при проектировании стало использование одномерных векторов для представления всех данных. В реализации используются стандартные одномерные массивы (векторы), элементы которых интерпретируются как байты (целые числа от 0 до 255).

Выбраны следующие структуры данных:
\begin{enumerate}
	\item \textbf{Глобальные константы.} Таблицы замен (S-Box и Inverse S-Box) хранятся как статические одномерные массивы длиной 256 элементов. Раундовые константы (Rcon) хранятся в векторе длиной 10 элементов.
	\item \textbf{Блок данных.} Представляется вектором фиксированной длины 16 байт. Одномерная структура упрощает операции копирования и доступ к памяти по сравнению с двумерной матрицей 4x4.
	\item \textbf{Расширенный ключ.} Все раундовые ключи хранятся в векторе длиной 44 элемента (где каждый элемент — 32-битное слово). Доступ к ключу конкретного раунда осуществляется через смещение индекса и распаковку слова на байты.
\end{enumerate}

\subsection{Архитектура программной системы}

Система построена по модульному принципу, где каждый файл отвечает за отдельный слой логики.

Взаимодействие модулей организовано следующим образом:
\begin{enumerate}
	\item Базовый модуль (structure.lsp) содержит математический аппарат и константы, не завися ни от каких других частей системы.
	\item Модуль ключей (key-module.lsp) использует константы базового модуля для генерации раундовых ключей.
	\item Модуль шифрования (encryption.lsp) реализует логику прямого преобразования данных и механизм дополнения (Padding).
	\item Модуль дешифрования (decryption.lsp) реализует логику обратного преобразования и восстановления исходных данных.
	\item Модуль тестирования (tests.lsp) является точкой входа и проверяет работу всей цепочки вызовов.
\end{enumerate}
